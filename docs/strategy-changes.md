# 策略配置与变更环境

已对照 Zeus 内容安全空间的变更环境页面与前端实现，保留顶部隔离提示及“取消变更、批量变更、变更内容、紧急变更、去实验”入口。读取来源时不写入 Zeus；实际编辑、发布和回滚均发生在本仓库服务的 SQLite 中。

## 生效约束

- 规则只要在任一普通、分层或路由场景生效（含灰度），其定义、删除、历史版本恢复和已有策略配置调整均必须进入策略变更。后端实施约束，不能仅绕过按钮发请求修改。
- 规则组新增规则只能选择离线或标记；新增规则同步到已有规则组挂载位置。没有生效引用的既有规则可直接调整或移除；有生效引用时，线上规则组编辑和删除不可用。
- 规则组保留批量操作、最后修改时间/修改人、规则标签及风险标签筛选；移除行内策略变更和引用按钮，从全局变更入口进入任务。

## 隔离、发布和同步

每个变更任务拥有独立草稿，通过 `changeTaskId` 传递上下文。查看规则、规则组、普通场景和分层节点时叠加该任务草稿；新开规则详情保留任务参数。未知任务或不受支持的变更写操作直接拒绝，不退回线上写入。

修改规则定义后，所有引用该规则的场景在发布时读取更新后的定义；修改单个场景策略只调整该场景配置；修改规则组策略则同步规则组的全部挂载配置，包括分层节点。删除规则会删除规则实体、引用配置和特征引用。多项变更在同一事务内发布，线上配置已经变化时拒绝陈旧草稿，避免部分发布。

“取消变更”退出环境并保留草稿，可从任务详情重新进入。“去实验”进入实验配置页；“紧急变更”进入灰度配置并填写原因。实验/审批后冻结草稿，最终发布时才写入线上配置；紧急变更同样不直接修改线上数据。发布保存快照，回滚恢复规则定义及相关配置；若发布后数据已被其他操作修改，则拒绝覆盖。

## 规则与风险标签

新建规则的三个环节为逻辑信息、测试、属性信息。交互式条件支持编号表达式，例如 `1&&(2||4)||3`、`!1||(2&&3)`，可以重复引用条件；服务端模拟计算采用解析器，不执行任意代码。模拟器覆盖布尔组合与基础比较，不等同于完整 Aviator 引擎。

引用统计区同时列出 Zeus 快照引用次数/决策比例，以及本副本实际引用配置数。全量规则定义不代表已经导入所有场景引用，两个数字可能不同，比例不会被伪造为次数。风险标签按 `parentId` 构建父子树，规则组及规则列表选中父标签时包含子标签。

## 验证

`npm test` 验证直接修改拦截、草稿隔离、分页与标签筛选、跨场景同步、删除级联、原子发布、配置冲突、回滚、紧急变更和自定义条件逻辑。`npm run build` 检查类型与生产构建。另用隔离内存数据库完成浏览器操作验收：生效策略进入变更环境、恢复编辑框、变更内容、实验页跳转、发布、规则组按钮/标签树及条件逻辑输入；不在源平台创建测试数据。

## 变更实验项配置

从变更环境点击“去实验”，打开独立的“变更实验项配置”页。顶部提供取消变更、返回变更环境和提交实验入口。页面包含双跑（比例、结束时间、流量来源、筛选条件）、历史（时长、流量来源）、基准评测（必防和回归样本），以及可切换的影响场景、模版、规则组、规则四类列表。查看实验内容可以对比当前草稿；对象名称在新标签页打开详情。

影响范围从当前任务的变更项及其实际引用计算，来源任务使用已有归档。样本量级来自已经导入的基准样本元数据，缺失的样本或预估耗时显示空值，不生成运行结果；有必做样本的业务不能取消基准评测。返回变更环境前保存配置，再次进入时恢复配置。提交前验证比例、时间、历史时长、条件和必做实验；本地模拟提交后冻结草稿，待配置灰度并提交审批，不发布规则、不向 Zeus 发起实验。

## 实验详情、灰度与发布

实验详情与实验项配置分别使用 `/release/experiment-detail`、`/release/experiment-config`。详情按双跑、历史、基准评测展示已导入的统计、场景对比、请求明细及流量信息；明细可搜索、分页、下载并跳转到策略排查。来源任务保持只读，不以空数据生成实验命中数。

“去变更”进入 `/release/gray-config`。日常变更首阶段比例为 1%–10%，后续严格递增且每次增幅不超过 50%，最终阶段固定 100%；非最终阶段观察时间至少 10 分钟。支持增删阶段、变更说明、指定审批人和通知人。提交前显示发布确认，提交后进入 `/release/approval-detail`；本地审批支持通过、驳回和撤回，未通过审批不能启动灰度。

灰度详情 `/release/gray-detail` 显示阶段、当前比例、观察时间、阶段数据对比/明细、已有趋势数据和操作记录。新流程按实际配置比例推进，不再固定每次 25%。中止后不能继续推进，可重启；最终阶段以事务统一发布相关配置。任务保存发布前快照及影响对象；即使规则/规则组配置已删除，发布后仍可核对影响列表和同步数量。回滚恢复全部关联配置；若发布后配置已被其他操作改动，拒绝覆盖。

紧急变更通过 `/release/gray-config?deployMode=0` 进入独立模式：填写紧急原因，选择灰度或全量，仍需确认与审批。紧急灰度非最终阶段至少 1 分钟；全量模式仅在审批后执行 100% 发布。可以返回变更环境继续编辑，未完整填写的灰度表单保留在当前浏览器会话草稿中。紧急变更跳过实验，不跳过审批。

本副本的实验提交、审批和手动推进用于验证界面与配置状态流转，不运行真实双跑任务、不切换真实灰度流量，也不向审批人或通知人发送外部消息。旧演示任务保留原有推进接口兼容；从新页面提交的任务使用配置阶段推进。

混合修改规则定义和规则组策略时，回滚按内容比较关联配置集合，忽略数据库记录读取顺序，但仍校验实际内容冲突；有直挂规则引用的场景也参与验证。
