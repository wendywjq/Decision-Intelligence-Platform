# 全量规则与特征目录

范围为 Zeus 境内生产环境的「35-内容安全」业务空间，包含列表中可见的全部规则状态；保留此前指定场景、规则组、分层场景和变更示例。

规则与特征目录采集于 2026-11-18，接口详情补采于 2026-11-19。数据包为可重建的离线快照。

本次快照收录 **28,583 条规则、61,655 个可用特征定义（43,478 个因子、18,177 个参数）**，并收录对应的 **6,583 份 RPC 依赖配置、4,602 个数据接口的入参详情**。另保留 141 个来源未提供定义的旧引用标记：137 个因子 ID 经查询明确返回不存在，4 个参数 ID 未出现在完整参数目录中。52 个依赖名称未能在源目录中匹配到定义，详见清单；没有生成替代逻辑。所有规则定义均已取得，没有以规则列表摘要代替缺失规则。

数据包位于 `fixtures/zeus-full-catalog/`，清单位于 `fixtures/zeus-full-catalog-manifest.json`。服务启动时校验每片摘要及整包摘要，再增量导入 SQLite。规则同时保存源表达式、交互条件、解析信息、模式配置以及列表标签元数据；特征保存源定义，包含目录中全部可见因子与参数，不再仅收录规则引用到的特征。来源目录计数保存在 `featureCatalogCounts`，打包与导入均核对各类条目数量和唯一 ID 数。

规则与特征之间同时按依赖名称和源 `factorIdList` 建立关联。参数 ID 在本地使用独立编码，避免与因子 ID 冲突。既有历史详情、场景绑定及本地修改不被本轮补充覆盖；本地删除记录不自动恢复。原快照中保留的历史规则和本地示例可能使列表总数略多于本轮源平台索引总数，以清单中的 `sourceTotal` 为本轮采集范围依据。

源平台不存在或无法解析的特征保留在清单的缺失与未解析列表中，不编造定义。没有逐条扩采规则的历史版本、测试记录及所有全局引用绑定；此前已采集的详情继续保留。

## 采集与访问控制

1. 使用已安装的 `zeus-auth` 技能验活并确认业务空间为 35；登录凭据不进入仓库。
2. 执行 `python3 scripts/capture-full-catalog.py`，再执行 `python3 scripts/expand-full-feature-catalog.py`，从已完整缓存的因子、参数目录扩展为全部可见特征。脚本只使用明确的查询接口，串行访问，每次完成请求后至少等待 1 秒。
3. HTTP 429、服务端繁忙及网络故障采用有限次数退避；认证失效立即停止。成功响应逐条缓存，重启后直接复用，不重新请求。
4. 源平台在分页过程中可能发生新增或修改；如果检测到索引重复，则独立复核分页，直到唯一 ID 数与源总数一致。三次复核仍变化则停止，避免无限请求。
5. 执行 `python3 scripts/resolve-full-catalog-features.py` 核查目录外的特征 ID，再重跑采集脚本离线合并核查结果，并再次执行 `expand-full-feature-catalog.py` 保持全量特征范围。执行 `python3 scripts/enrich-full-catalog-interfaces.py` 补齐 RPC 依赖配置与接口入参，已有完整缓存直接复用。
6. 完成后执行 `python3 scripts/pack-full-catalog.py`。未完成、规则定义缺失或包中含认证字段时拒绝打包。
7. 执行 `npm run verify:catalog`，逐条验证规则内容、特征定义及关联目标存在。

采集缓存、认证信息和运行进度位于被忽略的本地 `data/` 目录。Python 采集策略测试使用完全模拟的响应，运行测试不会访问 Zeus。
