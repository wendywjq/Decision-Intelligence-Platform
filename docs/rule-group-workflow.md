# 规则组配置与新建规则

规则组中的「添加规则」用于引用已有规则；「新建规则」进入逻辑信息、测试、属性信息三步向导。新增组内配置的默认状态为标记，只允许离线或标记。规则定义的就绪状态与场景中的策略生效状态分别保存。

规则组新增成员会在同一事务内同步到数据库中引用该组的普通场景、分层节点和上层规则组。即使删除最后一个成员，引用关系仍被保留，后续新增成员可以继续同步；循环引用不会重复展开。

修改和删除前，后端检查该规则在当前数据库的所有场景引用，包括其他规则组和直接挂载。只要任一场景生效或灰度执行，直接操作即返回 409，并要求走策略变更。此检查同时覆盖新接口、旧场景规则接口和导入配置编辑接口。判断依据是实际场景配置，不是规则定义自身的就绪状态。

「策略变更」可以提交修改或删除，创建包含变更前后内容的任务。任务经过既有实验、审批和灰度流程，最终发布后才同步实际配置。发布事务会核查配置是否已变化；回滚会恢复发布前的各场景配置，若发布后已有其他修改则拒绝直接覆盖。

三步向导支持交互式条件或表达式录入、测试结果与期望值比较、属性及风险标签配置、保存草稿和继续编辑。测试沿用本地受限表达式引擎；RequestId/CVID 模式读取已导入的日志示例，不调用线上审核服务。保存后测试记录、引用特征和场景引用均可继续查看。

验证包含新增状态限制、跨普通/分层场景同步、全场景生效检查、旧接口防绕过、嵌套与空组同步、变更发布及回滚，以及隔离数据库中的浏览器操作验收。本地操作不会写入 Zeus。
